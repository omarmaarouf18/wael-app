# Changes: Website Account Management, Legal Pages, Cart & Multi-Subject Orders (2026-11-05)

## Overview

This document records the changes implemented on the marketing and student sales website (`web/**`) for the 2026-11-05 parallel batch (Agent 4):
1. **Part A (Session Persistence)**: Fixed the web session bug where page navigation or reload logged the student out. Added client `AuthProvider` on mount with deduplicated `POST /api/v1/auth/refresh`, keeping the short-lived access token in JS memory while credentials (`refresh_token` cookie) persist across same-site navigations.
2. **Part E (Legal Pages from App)**: Replaced website legal placeholder text with permanent 308 redirects for `/terms`, `/privacy`, `/en/terms`, and `/en/privacy` to `https://legal.elmetracademy.app/terms` and `https://legal.elmetracademy.app/privacy` (with `#en` anchor on English routes). Direct links in header/footer and forms. Added legal consent agreement notice to signup, checkout, and single-subject buy forms. Kept `/refund` and `/en/refund` as owner TODO placeholders and documented the content gap.
3. **Part B (Account Management on Web)**: Mirrored mobile app student account features on `/account`:
   - Profile management: display name, email, phone; edit name and add/change phone with current password confirmation via `PATCH /auth/me` (first phone anytime, later changes enforce the 30-day rule with `change_too_soon` retry handling).
   - Password management: change password via `POST /auth/password/change` with current password verification and confirmation match; quick link to `/forgot-password`.
   - Devices & sessions: list active sessions via `GET /auth/sessions` with `current` and `web` session badges (web sessions do not count against the 2-device cap); individual session termination via `DELETE /auth/sessions/{sid}` with automatic local logout if current session is signed out.
   - Notifications inbox: list student alerts and broadcast messages via `GET /notifications/list` and mark read via `POST /notifications/read` (using on-demand HTTP polling; live SSE omitted on web for simplicity).
   - My subjects: list active entitlements with public catalog title resolution, "Study in app" banner, and official App Store and Google Play store links.
   - Account deletion: two-step confirmation requiring the exact typed word "حذف" (or "delete" on English) and current password via `POST /auth/account/delete`; displays scheduled 30-day purge date and triggers site-wide logout.
4. **Part C (Website Cart, Checkout & My Orders)**:
   - Cart: browser-persisted `localStorage` state with resilient `try/catch` error handling; add/remove subjects, price and total calculations, duplicate prevention, and refusal of owned or pending subjects.
   - Checkout: slide-over drawer modal supporting payment method selection (`wallet` or `instapay` from `GET /academy/payment-methods`), transfer reference, sender number, amount paid, and legal agreement notice; submits to `POST /academy/orders` and clears the cart on success.
   - My Orders: tab on `/account` rendering orders from `GET /academy/me/orders` (with fallback to `GET /academy/me/requests`) detailing order ID, date, transfer reference, sender number, amount paid, total, and per-subject status (`pending`, `accepted`, `rejected` with administrative reject reason).
5. **Static Pages & Store Safety**: Maintained strict Next.js route classification where catalog and marketing pages remain prebuilt static (`○` and `●`), while dynamic forms remain isolated to `/account`, `/login`, `/signup`, `/forgot-password` (and their `/en` counterparts). No wallet numbers, InstaPay addresses, cart references, or buy links exist in `frontend/`.

## Proposed Amendments to Shared Documentation

### 1. Target Doc: `docs/adr/0014-sales-website.md`

#### Section: Decision 4 (Purchase requests & checkout)
**Amendment (Dated 2026-11-05, Multi-subject Cart & Orders):**
> *Amended 2026-11-05 (Agent 4 batch):* In addition to single-subject purchase requests, the website provides a client-side shopping cart enabling multi-subject checkout in a single payment transaction.
> - **Cart Storage**: Stored in browser `localStorage` under `elmetr_academy_cart_v1` with JSON validation and graceful fallback for corrupt data or restricted storage environments. Cleared upon successful checkout.
> - **Checkout Submission**: Calls `POST /api/v1/academy/orders` with `claims.client == "web"`, passing `subject_ids` (1–50 items), `payment_method` (`"wallet"` | `"instapay"`), `transfer_reference`, `sender_number`, and `amount_paid`.
> - **Error Handling**: Displays typed bilingual error messages returned by academy-service (`already_owned`, `pending_request_exists`, `duplicate_reference`, `subject_expired`, `invalid_amount`) naming the specific subject where applicable.
> - **Order History**: Exposes `GET /api/v1/academy/me/orders` on the `/account` hub, showing order date, proof fields, total, and individual per-subject statuses (`pending`, `accepted`, `rejected` with `reject_reason`).

#### Section: Decision 7 (Auth and session persistence)
**Amendment (Dated 2026-11-05, Client AuthProvider & Session Persistence):**
> *Amended 2026-11-05 (Agent 4 batch):* The website maintains session persistence across navigations and page reloads via a client-side `AuthProvider`:
> - On initial mount, `AuthProvider` calls `POST /api/v1/auth/refresh` with `credentials: "include"` and header `X-Client: web`. Concurrent refresh requests are deduplicated into a single in-flight promise.
> - The short-lived access token is stored strictly in JavaScript memory (`inMemoryAccessToken`) and passed via `Authorization: Bearer <token>` on authenticated API requests.
> - A `401 Unauthorized` response on refresh silently clears state to unauthenticated without displaying error banners to visitors.
> - Header navigation dynamically renders login/signup links when unauthenticated and Account/Logout controls when authenticated.
> - Web sessions are labeled `"web"` in device session listings and are exempt from the mobile 2-device cap.

2. Refund eligibility criteria (e.g., refund window from grant, non-refundability once video streaming or lesson access has begun).
3. Processing timelines and dispute resolution for incorrect or unmatched transfer references.

**Action Taken**: `/refund` and `/en/refund` remain as owner TODO pages clearly stating that refund terms are pending owner publication, rather than authoring unofficial legal text.
